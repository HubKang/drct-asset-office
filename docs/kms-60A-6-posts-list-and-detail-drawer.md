# 60-A-6 KMS 지식게시판 리스트형 탐색 UX 개편

## 작업 목적

KMS 지식게시판의 카드형 탐색 구조를 리스트형 탐색 구조로 개편했다. 게시글을 더 빠르게 훑고 비교할 수 있도록 좌측 카테고리 리스트, 중앙 게시글 목록, 우측 상세 drawer 구조를 적용했다.

## 기존 카드형 UX 문제점

- 게시글 카드가 많은 세로 공간을 사용해 정보 밀도가 낮았다.
- 게시글을 클릭하면 상세 페이지로 이동해 목록과 상세를 오가며 비교하기 어려웠다.
- 카테고리가 카드처럼 보이는 구조라 게시글 수를 빠르게 파악하기 어려웠다.

## 카테고리 리스트 변경 내용

- 카테고리 영역을 compact list 형태로 변경했다.
- “전체”를 최상단에 고정 표시한다.
- 카테고리명 오른쪽에 활성 게시글 수 badge를 표시한다.
- 선택된 카테고리는 배경색과 좌측 accent bar로 강조한다.
- 게시글 수는 검색/필터와 무관한 전체 활성 게시글 기준으로 계산한다.

## 게시글 목록형 변경 내용

- 카드형 게시글 목록을 compact table/list 형태로 변경했다.
- 기본 컬럼은 제목과 수정일이다.
- 제목 아래에 카테고리, 중요도, 학습 상태, 태그, 요약 미리보기를 작은 메타 정보로 표시한다.
- row hover 효과와 선택 row 강조를 적용했다.
- 긴 제목과 메타 정보는 말줄임 처리한다.

## 상세 Drawer 구조

- 게시글 row 클릭 시 오른쪽에서 상세 drawer가 열린다.
- drawer 너비는 데스크톱 기준 60vw이며 최대 1120px이다.
- drawer 안에는 제목, 상태 badge, 태그, 요약, sanitize된 HTML 본문, 참고 URL, 작성일/수정일 메타 정보를 표시한다.
- 본문 HTML 렌더링은 기존 DOMPurify sanitize 흐름과 KMS rich content 스타일을 유지한다.
- 수정 버튼은 기존 `/kms/posts/:postId` 상세/수정 라우트로 이동한다.

## 20건 페이징 처리 방식

- 프론트엔드에서 현재 조회된 게시글 목록을 20건씩 slicing한다.
- 현재 페이지, 총 페이지 수, 이전/다음 버튼, 페이지 번호 버튼을 제공한다.
- 카테고리 변경, 검색, 필터 변경, 초기화 시 page=1로 돌아간다.

## 기존 상세 라우트 유지 여부

- 기존 `/kms/posts/:postId` 상세 라우트는 유지했다.
- 목록 화면에서는 drawer로 상세를 열고, 직접 URL 접근 또는 수정은 기존 상세 페이지를 사용한다.

## Backend 변경 여부

- backend 변경 없음.
- 카테고리별 게시글 수는 기존 게시글 목록 API를 별도로 호출해 프론트에서 계산한다.

## DB 변경 여부

- DB 변경 없음.
- 기존 KMS 테이블 삭제/초기화 없음.

## 기존 기능 영향 여부

- 새 지식 등록 폼과 Rich Editor는 유지했다.
- 검색, 카테고리 필터, 학습 상태 필터, 중요도 필터를 유지했다.
- 태그 저장, HTML sanitize, 이미지 표시 흐름을 유지했다.

## 남은 이슈

- 카테고리별 게시글 수는 현재 프론트에서 최대 1000건 기준으로 계산한다.
- 게시글이 크게 늘어나면 backend에서 category count와 total count를 제공하는 API 확장이 더 적합하다.
- drawer에서 바로 inline 수정하는 기능은 구현하지 않았다. 수정은 기존 상세 페이지로 이동한다.
