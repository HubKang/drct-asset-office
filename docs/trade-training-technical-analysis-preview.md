# 매매훈련 계산 전용 기술분석

## 구조 감사

- 계좌관리 매매훈련과 종목 매매훈련은 모두 `TradeTrainingPage.tsx`의 동일한 `CandleChart` SVG를 사용한다.
- 캔들·거래량·이동평균은 `TradeTrainingService.get_session_detail`에서 현재 `current_index`까지만 공개한다. ‘다음’은 서버의 인덱스와 `current_date`를 한 거래일 진행한다.
- 코스피·코스닥 비교는 별도 지수 API를 사용한 뒤 현재 훈련 기준일 이하로 제한한다.
- 수평선·수동 추세선은 `CandleChart` React state에만 존재한다. 선택/전체 삭제는 이 사용자 작도만 대상으로 한다.
- 리스크 계획선·도달선은 리스크 시나리오 데이터로부터 별도 SVG 레이어에 표시되며 사용자 작도 삭제 대상이 아니다.
- 기존 시장 신호 추세 구현은 계산과 저장 평가가 한 서비스 안에 있었다. 매매훈련은 저장형 시장 신호 경로를 호출하지 않고 새 순수 계산 모듈만 호출한다.

## 계산 및 보존 경계

`POST /trade-training/technical-analysis/preview`는 세션 ID로 종목과 현재 기준일을 검증한다. 클라이언트 기준일은 세션 `current_date`를 넘을 수 없고, 가격 조회 SQL 자체에 `trade_date <= :end_date`가 적용된다.

표시 기간과 회귀 분석 기간은 분리한다. 회귀는 기본 120개 봉(최대 240개 설정)만 사용하고, 가격 조회도 표시·준비 구간을 합친 최대 600행으로 제한한다. 응답에는 OHLCV를 중복 포함하지 않고 오버레이 최소 좌표와 집계 수치만 반환한다.

분석 결과와 설정은 다음 위치에서만 일시적으로 유지된다.

- 현재 React 화면 상태
- 서버 프로세스 내 5분 TTL, 최대 128개 LRU 캐시

DB 테이블·컬럼·마이그레이션, SQLite/파일/Redis 캐시, localStorage/sessionStorage/IndexedDB 저장을 추가하지 않았다. 매수·매도·다음·종료·복기·리스크 계획 경로에도 분석 값을 전달하지 않는다. 서버 재시작, TTL 만료, 페이지 이탈 또는 세션 변경 시 임시 상태는 사라진다.

## 미래 데이터 및 피벗

모든 이동평균, 회귀 채널, 거래량, ATR, 가격 범위와 캔들 계산은 서버에서 기준일 이하로 잘린 배열만 사용한다. 스윙 확정점은 좌우 확인 폭이 모두 기준일 이하에 있는 경우만 확정하며, 기준일 인접 값은 후보로만 표시한다.

## UI

차트 툴바는 작도·분석·비교·관리 그룹과 기간 segmented control로 구성한다. 자동 분석을 켜면 회귀선, 상하 채널, 분석 시작선, 옅은 분석 구간과 현재점이 표시된다. 요약 스트립은 최대 핵심 4개 정보만 노출하며 상세 Drawer의 종합·추세·이동평균·거래량·가격 위치 탭은 한 번 받은 응답을 재사용한다.

설정 조정은 ‘현재 화면에 적용’으로만 동작하며 저장 버튼이나 시그널/스냅샷 생성 동작은 제공하지 않는다. 연속 기준일 변경 시 이전 HTTP 요청을 취소하고 요청 순번으로 최신 결과만 반영한다. 분석 실패는 차트·주문·다음 진행을 막지 않는다.

- 기존 차트 preview 테스트: 사전 30봉 공개와 이동평균 준비 구간 회귀 검증

성능 수치는 실제 테스트 실행 결과만 최종 작업 보고에 기록한다.
