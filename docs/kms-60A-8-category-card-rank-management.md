# KMS 카테고리 카드형 관리 및 드래그 순위 저장

## 작업 목적

KMS 설정의 카테고리 관리 화면을 기존 목록+폼 구조에서 카드형 관리 UI로 개편했다. 카테고리 등록, 수정, 활성/비활성, 조건부 삭제, 순위 편집과 저장을 카드 중심으로 처리할 수 있게 했다.

## 기존 UX 문제점

- 좌측 목록과 우측 폼 구조가 넓은 여백을 만들고, 각 카테고리의 상태와 사용량을 한눈에 보기 어려웠다.
- 카테고리 순서 조정이 숫자 입력 중심이라 실제 표시 순서를 직관적으로 바꾸기 어려웠다.
- 삭제와 비활성화 동작의 의미가 명확히 구분되지 않았다.

## 카드형 카테고리 관리 방식

- 카테고리를 카드 그리드로 표시한다.
- 각 카드에는 카테고리명, 대분류/하위분류, 표시 순서, 활성 상태, 활성 게시글 수, 하위 카테고리 수, 수정일을 표시한다.
- 카드 하단에서 수정, 활성/비활성, 삭제를 수행한다.
- 등록/수정은 카드 목록 위의 별도 편집 패널에서 수행한다.

## 활성/비활성 정책

- 활성/비활성은 `PATCH /kms/categories/{category_id}/active`로 처리한다.
- 비활성화는 실제 삭제가 아니며 `is_active=false`만 반영한다.
- 기존 게시글과 연결된 카테고리도 비활성화할 수 있다.

## 삭제 정책

- `DELETE /kms/categories/{category_id}`는 조건부 실제 DB 삭제로 변경했다.
- 삭제 가능 조건:
  - 해당 카테고리에 연결된 전체 게시글 수가 0
  - 하위 카테고리 수가 0
- 게시글이 있으면 삭제를 차단하고 비활성화를 안내한다.
- 하위 카테고리가 있으면 삭제를 차단하고 하위 카테고리 정리를 안내한다.
- frontend에서도 전체 게시글 참조 또는 하위 카테고리가 있으면 삭제 버튼을 비활성화한다.

## 순위 편집/드래그&드랍 UX

- 순위 편집 버튼을 누르면 카드가 드래그 가능한 상태로 전환된다.
- 카드를 드래그해 위치를 바꾸면 화면 순서가 즉시 바뀐다.
- 취소 버튼은 편집 전 순서로 복원한다.
- 자동순위로 초기화는 기본 대분류 순서 기준으로 화면 순서를 재정렬하며, 즉시 저장하지 않는다.

## Sort Order 저장 API

- `PUT /kms/categories/sort-orders`
- 요청:

```json
{
  "items": [
    { "id": 1, "sort_order": 10 },
    { "id": 2, "sort_order": 20 }
  ]
}
```

- 응답:

```json
{
  "success": true,
  "updated_count": 2
}
```

- 존재하지 않는 카테고리, 중복 id, 중복 sort_order는 오류로 처리한다.

## Backend/DB 변경 여부

- backend API, schema, service를 KMS 카테고리 관리 범위에서 수정했다.
- DB 테이블 구조 변경은 없다.
- 기존 KMS 테이블 삭제/초기화는 없다.

## 기존 기능 영향 여부

- KMS 홈, 지식게시판의 기존 카테고리 조회 API는 유지된다.
- 카테고리 응답에 `post_count`, `total_post_count`, `child_count` 필드만 추가되어 기존 사용처와 호환된다.
- 기존 게시글 데이터와 태그 데이터는 변경하지 않는다.

## 남은 이슈

- MVP에서는 카드를 하나의 목록에서 드래그한다. 하위 카테고리의 parent 그룹별 독립 정렬은 후속 개선으로 분리할 수 있다.
- 삭제 버튼은 화면에서 사전 비활성화하지만, 최종 삭제 가능 여부는 backend에서 다시 검증한다.
