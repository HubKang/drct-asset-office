# 데이터 보존 정책

## 기본 원칙

- 기능에서 재사용하지 않는 원천 응답, 검증 표본, 시뮬레이션 표본 및 차트 시계열은 DB에 영구 저장하지 않는다.
- 검증·시뮬레이션 실행 상세는 요청 응답 또는 실행 중 메모리에서만 사용한다.
- DB에는 운영 판단, 이력 표시 및 비교에 필요한 집계값만 저장한다.

## JSON 컬럼 규칙

- JSON 컬럼을 추가하거나 확장하기 전에 저장 목적, 실제 조회 필드 및 보존 기간을 정의한다.
- 상세 결과를 통째로 저장하지 않고 집계 필드 허용 목록 방식으로 저장한다.
- 목록·상세 API는 내부 JSON 원문을 기본 반환하지 않고 화면에 필요한 명시적 집계 필드만 응답한다.
- 원천 응답이나 재생성이 가능한 시계열이 꼭 필요하면 DB 외부의 별도 보관 정책과 만료 기간을 먼저 정의한다.

## 정리 절차

- 기존 상세 데이터는 DB 백업 후 트랜잭션으로 집계 형태로 축약한다.
- SQLite 파일의 물리 공간 회수는 축약 결과를 확인한 다음 `VACUUM` 또는 `VACUUM INTO` 절차로 수행한다.
- 축약 후에도 운영 판정에 필요한 집계값과 검증 완료 상태는 유지한다.

## 시장 지표 시그널

`market_signal_definitions.validation_summary_json`과
`market_signal_rule_experiments.validation_summary_json`에는 다음 범주의 값만 저장한다.

- 표본·발생·확인·무효화·해제 건수
- 상태별 건수와 비율
- 평균·중앙값·최댓값 등 지속 기간 및 점수 집계
- 조건별 통과 건수와 기여도 집계
- 검증 경고와 룰 변형별 집계

`recent_samples`, `latest_sample`, `series`, `transition_points`, 개별 평가 근거 원문은 저장하지 않는다.
