# DrCT 종목 시그널 Phase 6-C.4 자동 개선 검증

## 사용자 중심 자동 개선

사용자는 성공 차트마커의 품질만 관리한다. 새 성공(S) 사례가 추가되면 기존 패턴 Signature와 현재 후보는 다음 Scan에서 자동으로 다시 계산된다. 추천 계산 방식 자체의 변경안은 별도로 검증하며, 검증 결과가 좋아도 운영 기준을 자동 교체하지 않는다.

자동학습은 현재 알고리즘의 학습값을 갱신하는 과정이고, 알고리즘 개선은 후보를 고르는 계산 방법을 바꾸는 과정이다. 화면에서는 이를 각각 `자동학습`과 `추천 개선안`으로 구분한다.

## 현재 방식과 추천 개선안

- 현재 방식: `CANDIDATE_POLICY_BASELINE_V1`. 과거 성공 사례 유사도 분포의 P25 이상을 운영 후보로 유지한다.
- 추천 개선안: `CANDIDATE_POLICY_SHADOW_V1`. 현재 방식 기준과 현재 시장 분포 P90을 모두 충족하는 후보를 비교한다.
- 일반 화면에는 P25, P90, LOO, Universe, SHADOW 같은 내부 용어를 표시하지 않는다. 상세 정보에서만 확인할 수 있다.

## 과거 성공 사례 재검증

Marker의 성공 사례를 날짜순으로 정렬한다. 대상 성공 사례 D0를 검증할 때는 `marker_date < target_d0`인 이전 성공 사례만 Signature 학습에 사용한다. 대상 사례 자신과 같은 날 또는 미래의 Marker는 포함하지 않으며, 가격도 D0까지만 사용한다.

이전 CORE-ready 성공 사례가 3건 미만이면 검증하지 않는다. 3~4건은 참고 검증, 5건 이상은 정식 검증으로 구분한다. 각 검증에서 현재 방식과 추천 개선안이 실제 성공 종목을 후보로 다시 탐지했는지와 당시 평균 후보 수를 계산한다.

## Historical Universe 정책

`market_theme_stocks`에는 연결의 과거 유효 시작·종료 이력이 없다. 따라서 이번 단계는 현재 활성 테마 연결종목을 각 과거 D0 가격으로 평가하는 `CURRENT_ACTIVE_APPROXIMATION`을 사용한다. 과거 테마 구성까지 완전히 복원한 Backtest는 아니다. 이 제한은 일반 화면이 아니라 알고리즘 상세에서만 안내한다.

## 자동 개선 상태

- `NEED_MORE_DATA` → 데이터 더 필요: 검증 가능한 과거 사례가 3건 미만이다.
- `VALIDATING` → 자동 검증 중: 데이터가 있으나 개선 판단 조건이 아직 충족되지 않았다.
- `IMPROVEMENT_READY` → 개선안 검토 가능: 과거 성공 사례를 모두 유지하고 평균 후보를 20% 이상 줄였다.
- `KEEP_CURRENT` → 현재 방식 유지: 개선안이 현재 방식이 찾은 과거 성공 사례를 놓쳤다.

`IMPROVEMENT_READY`는 검토 신호일 뿐 자동 승격 조건이 아니다. 이번 단계에는 개선안 적용 API나 버튼이 없다.

## 실행과 저장 정책

과거 재검증은 메인 종목 시그널 Scan에서 실행하지 않는다. 추천 기준 점검 또는 Marker 학습 상태를 열 때 Marker 단위로 지연 실행한다. 결과는 Engine, Marker, 분석일, 성공 사례, 현재 Universe, 가격 갱신 버전을 키로 하는 bounded runtime memory cache에서만 재사용한다.

신규 Table과 Migration은 없으며 Historical Feature Matrix, 과거 Scan, 후보 JSON, Similarity Matrix 및 Validation 결과를 저장하지 않는다.

## 장기 알고리즘 개선 원칙

1. 새 성공 사례는 자동학습한다.
2. 기존 알고리즘의 학습값과 후보를 자동 재계산한다.
3. 개선 알고리즘은 운영 결과와 분리해 검증한다.
4. 과거 성공 사례를 미래 데이터 없이 재현 검증한다.
5. 성공 사례 탐지를 유지하면서 후보 범위를 줄인 경우에만 승격을 검토한다.
6. 검증 없이 운영 알고리즘을 자동 교체하지 않는다.
7. 사용자는 학습 데이터 품질만 관리한다.
