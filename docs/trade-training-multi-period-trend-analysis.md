# 매매훈련 다중 기간 추세·변곡 분석

## A. 기존 구조 감사

- 메인 차트의 캔들 표시 기본값은 훈련 세션 `display_days=80`이다.
- 기존 기술분석 미리보기는 `/trade-training/technical-analysis/preview` 한 요청에서 추세·이동평균·거래량·가격 위치·캔들 데이터를 함께 반환했다.
- 회귀 기울기, 정규화 기울기, R², 추세 강도, 채널 위치는 `calculate_regression_channel`을 통해 시장 신호 관리와 매매훈련이 공통 사용한다.
- 기존 상세 Drawer는 1M·3M·6M·1Y·ALL 중 한 기간만 요청했고, 기간 전체 방향과 현재 진행 추세를 분리하지 않았다.
- 기존 상세 Drawer는 수치 탭만 제공했으며 별도 캔들차트, 현재 추세 시작점, 상태 시계열, 전환 이력은 없었다.
- 분석 결과·설정·캐시는 DB에 기록되지 않았다. 기술분석 선택 기간과 설정을 브라우저 저장소에 기록하는 코드도 없었다.

## C. 메인 80봉 간편 분석

메인 차트는 기존 미리보기 API를 유지하며 백엔드에서 `trend_window=80`을 강제한다. 프런트 요청값으로 이 기준을 늘릴 수 없다. 메인 툴바에는 기간 버튼을 표시하지 않는다.

표시 문구:

- 자동 추세분석
- 최근 80봉 간편 분석

회귀선·채널·분석 시작점·현재값 오버레이는 기존 메인 캔들차트에 그대로 표시된다.

## D. 다중 기간 계산

전용 API:

`POST /trade-training/technical-analysis/multi-period-preview`

요청 필드:

- `training_session_id`
- `stock_code`
- `as_of_date`
- `selected_period`
- `configuration`

응답은 1M·3M·6M·1Y·ALL 요약과 선택 기간 상세를 함께 반환한다. DB 가격 조회는 요청당 한 번이며 반환된 배열을 메모리에서 기간별로 자른다.

기간별 기본 프로필:

| 기간 | 모델 | 민감도 | 현재 구간 최대 창 | 최소 관측값 |
|---|---|---|---:|---:|
| 1M | 단기 추세형 | 빠름 | 12 | 8 |
| 3M | 스윙 추세형 | 민감 | 24 | 15 |
| 6M | 중기 추세형 | 보통 | 40 | 20 |
| 1Y | 장기 맥락형 | 완만 | 60 | 30 |
| ALL | 전체 맥락형 | 완만 | 80 | 30 |

내부 숫자는 사용자 카드에 직접 노출하지 않고 모델명과 민감도로 설명한다.

## E. 기간 전체 방향과 현재 진행 추세

기간 전체 방향은 선택 기간 전체 종가의 회귀 기울기와 R²로 계산한다.

- 상승
- 하락
- 횡보
- 방향성 불명확
- 데이터 부족

현재 진행 추세는 각 거래일을 순서대로 평가한 상태 시계열의 마지막 확정 방향과 상태로 계산한다. 두 결과는 서로 덮어쓰지 않는다.

예를 들어 기간 전체 방향이 상승이고 현재 추세가 하락인 혼합 상태를 그대로 반환하고 쉬운 설명으로 조합한다.

## F. 인과적 상태 시계열과 시작점

`calculate_trend_state_series`는 각 날짜에서 그 날짜까지의 데이터만 사용한다. 미래 캔들을 참조하지 않는다.

각 점은 다음을 포함한다.

- 관측일
- 현재 추세 방향
- 전환 상태
- 기울기
- 정규화 기울기
- R²
- 채널 위치
- 추세 강도
- 추세 지속 봉 수
- 현재 추세 시작일

상태:

- 추세 확정
- 추세 유지
- 추세 약화
- 추세 이탈 후보
- 추세 이탈 확인
- 일시 이탈 후 복귀
- 반전 후보
- 반전 확인
- 기존 추세 재개
- 횡보
- 데이터 부족

방향 후보와 이탈 후보는 기간 프로필의 지속 봉 수를 충족해야 확정된다. 마지막 확정 방향 전환일을 현재 추세 시작일로 사용한다.

계산은 기간별 고정 최대 rolling window만 다시 계산한다. 전체 prefix를 매번 회귀하는 무제한 O(N²) 방식은 사용하지 않는다.

## G. 전환 이력

상태가 실제로 변경되고 표시 대상 상태에 진입한 경우에만 이벤트를 만든다. 동일 날짜·동일 상태 이벤트는 반복 생성하지 않는다. 선택 기간 상세에는 최근 5건만 역순으로 반환한다.

각 이벤트:

- 전환일
- 이전 상태와 현재 상태
- 당시 방향
- 핵심 근거
- 당시 추세 강도
- 당시 채널 위치

이벤트는 응답 메모리에서만 존재한다.

## H. 상세 캔들차트

상세 추세 탭은 선택 기간 전체 OHLCV를 캔들로 표시한다.

- MA5·MA10·MA20·MA60·MA120
- 거래량
- 현재 추세 시작 세로 점선
- 현재 추세 구간 중립 음영
- 현재 추세 회귀선
- 채널 상·하단
- 현재값 작은 원
- 최근 전환 삼각형 마커

회귀선과 채널은 현재 추세 시작일 이후에만 생성한다. 분석 구간 이전 캔들은 정상 표시한다.

## I. 종합 탭 정합성

종합 탭은 1M 단기, 6M 중기, 1Y 장기 결과를 별도로 보여주며 단기·중기 방향 일치 여부를 설명한다. 결과를 매수·매도 판단이나 추천으로 압축하지 않는다.

기존 이동평균·거래량·가격 위치 탭은 선택 기간 상세 응답을 함께 사용하므로 기간을 바꾸면 같은 기준으로 갱신된다.

## J. 요청 취소와 캐시

- 프런트는 메인 분석과 상세 분석에 별도 `AbortController`와 요청 번호를 사용한다.
- 빠르게 기간을 바꾸면 이전 요청을 취소하고 마지막 응답만 반영한다.
- 탭 전환은 API를 다시 호출하지 않는다.
- 백엔드는 5분 bounded TTL 메모리 캐시를 사용한다.
- 캐시 키에는 세션, 종목, 기준일, 선택 기간, 설정 해시, 최신 가격일이 포함된다.
- DB, 파일, localStorage, sessionStorage, IndexedDB에는 분석 결과와 설정을 저장하지 않는다.

## K. 성능 측정

실제 세션 85, 기준일 2026-01-16, 조회 11봉:

- DB 조회: 1.257ms
- 5개 기간 요약: 3.233ms
- 추세 시작점 탐지 합계: 3.219ms
- 선택 기간 상세: 1.295ms
- 계산 합계: 3.323ms
- API 전체: 11.105ms
- payload: 12,600 bytes

결정론적 합성 OHLCV, ALL 상세 순수 계산 벤치마크:

| 봉 수 | 계산 wall time | payload |
|---:|---:|---:|
| 500 | 150.187ms | 150,704 bytes |
| 1,000 | 271.213ms | 281,160 bytes |
| 2,000 | 381.995ms | 539,313 bytes |

합성 측정은 DB 조회 시간이 포함되지 않은 순수 계산값이다. 실제 API 수치와 혼합해 해석하지 않는다.

## L. 미래 데이터 차단

서비스는 세션의 실제 `current_date`보다 큰 클라이언트 기준일을 세션 기준일로 제한한다. 저장소 쿼리에도 `trade_date <= :end_date`가 적용된다.

기간 전체 방향, 상태 시계열, 시작일, 전환 이력, 회귀선, 채널, 이동평균, 거래량, 스윙, 현재 캔들은 모두 제한된 배열만 사용한다. 테스트에서는 극단적인 미래 시세를 추가한 전후 응답이 동일함을 비교한다.

## N. 남은 제한

- 상태 전환은 설명 가능한 회귀·지속성 규칙이며 통계적 최적 매매 신호가 아니다.
- 일봉 사이의 장중 전환 순서는 복원하지 않는다.
- ALL 가격 조회 상한은 현재 5,000봉이다.
- 데이터가 최소 관측값보다 적은 기간은 다른 기간을 막지 않고 개별적으로 데이터 부족 처리한다.
